できること

  • ひとりで最後まで持っていく

    設計・実装・公開・運用まで、ひとりで回します。下の8つは全部、配布か本番稼働まで出しています（Sirube・Sudare・Warframe State Graph はリリース配布、loopfinder は VS Code Marketplace、grounding-check は GitHub で公開、焦点距離チェッカー・CMS・Ruv は Cloudflare 上で稼働中）。

  • 推測で決めず、実物で確かめる

    「動くはず」で止めず、実際に動かして差を見ます。loopfinder は「フックあり／なし」の両側をテストで確かめ、CMS はデプロイの後に、拒否されるべきリクエストを実際に投げています。

  • 制約の中で設計する

    予算・API・権限が足りないことを前提に形を決めます。Ruv は無料枠の CPU 10ms に収まるよう処理を段に分け、Warframe State Graph は所持状態を取れる公式 API が無いので、自動同期をやめて1タップの入力にしました。

  • 人に分かる形にする

    作った仕組みを、他の人が読める文章に起こします。CMS の防御は Zenn の本に、Ruv の記憶の設計は記事にまとめています。

    作ったもの

    移行・保守

    上の CMS を載せた個人サイト（Astro + Cloudflare Workers）を、本番で動かしたまま上げ続け、直し続けている記録です。

    • フレームワークのメジャー移行（Astro 5 → 6 → 7）

      5 → 6 では、Cloudflare Pages だとページの生成中に自分の API を呼べない（1042 Loopback）ことに移行の途中で当たり、Pages をやめて構成ごと Workers へ移しました。データは HTTP 経由をやめ、R2・KV を直接読む層から取っています。6 → 7 では、ビルドが「Astro のバグかもしれない」というエラーで止まりました。上流の未解決 issue に原因を求めかけましたが、追い直して、自分の package.json の overrides が Vite を古い版に固定していたのが原因だと突き止めました。公開後に出た、CSS の圧縮でぼかし（backdrop-filter）が消える不具合も直しています。

    • 遅いところを測って直す

      あるページが KV を14回、順番に待って読んでいて、エッジのキャッシュが冷えていると表示まで約3.7秒かかっていました。読みを並列にまとめ、キャッシュが冷えた状態で計り直して 3.75秒 → 0.34秒（約11倍）にしています。管理画面で全件を1件ずつ取りに行っていた（N+1）のは、作ってある索引から読むように直しました。API が no-store を返していてキャッシュのヒット率が 0.9% だったのも、原因を見つけて外しています。

    • 自分の本番を点検して塞ぐ

      公開している API とアップロードの経路を一通り点検し、ログインしていなくても書き込める口や、宣言された Content-Type をそのまま信じて配信していた口などを見つけて塞ぎました。ストレージの公開設定のせいで原本の画像が誰でも取れる状態になっていたときは、まず公開を止め、配信経路の漏れは後から直しています。一度直したはずの防御が後の変更で気づかないうちに戻っていたことが2回続いたので、「拒否されるべきリクエスト」を投げるテストを用意し、デプロイのたびに CI で流しています。

    • 依存の更新を止めない

      依存の更新が手作業任せで遅れていたので Dependabot を入れ、その後、更新の PR が CI の権限不足で全部落ちて溜まっていたのも直しました。メジャー更新（zod v4）で管理画面のエラー表示が壊れたまま3か月本番に残っていた件は、本番で気づいてから原因を辿って直しています。GitHub Actions の Node 20 廃止には期限の前に対応し、毎週、依存パッケージの差分と Cloudflare の変更履歴を読んで、当てはまるものをチケットにしています。
